# 07：悬浮字幕窗口与会议助手视图

## 当前已经能做什么

Meetily 现有悬浮字幕不是嵌在主窗口里的面板，而是一个独立的 Tauri 原生窗口。它可以始终置顶并跨应用显示，因此用户在看视频、飞书文档、设计稿或技术方案时，不必把 Meetily 主窗口留在前台。

当前切片已完成：

- 独立透明字幕窗口，默认隐藏、始终置顶、不占任务栏、无系统边框；
- 独立字幕设置窗口，设置项不再受字幕窗口高度裁切；
- 窗口宽度 `360–1600` 像素、高度 `100–480` 像素、字号 `16–56` 像素，设置页同时显示当前值和范围端点；
- 背景不透明度 `0–100%`，修改后即时应用并自动保存；
- 鼠标穿透，可从 Meetily 主窗口或系统托盘恢复；
- 可选的屏幕分享保护，调用系统窗口内容保护能力；
- 字幕窗口物理坐标持久化，重新显示或重启后恢复，并在显示器布局变化时回收到最近工作区；
- 简体中文状态、按钮、空态、范围单位和失败提示；翻译失败使用固定安全文案，不展示 provider 返回的内部标识或错误堆栈；
- 使用可修订转写 reducer，拒绝重复、乱序和旧修订；
- 窗口重新显示时主动读取录音状态和转写历史，不依赖“刚好没错过事件”；
- 设置窗口优先放在字幕条下方，空间不足时移到上方，并限制在字幕所在显示器的工作区内；拖动字幕时已打开的设置窗口会跟随；
- 设置窗按当前显示器缩放比例换算物理尺寸；工作区小于默认尺寸时保留边缘间距并缩到可见范围，内容继续在窗内滚动。
- 字幕、要点、待办三种紧凑模式，默认模式会随其他悬浮窗设置一起保存；
- 字幕模式保留原文优先的低延迟双语显示，译文失败不会覆盖原文；
- 要点模式显示议题、决定、风险、待确认问题，待办模式显示行动项、负责人和截止时间；
- 要点和待办只订阅 Rust 后端公开的实时总结快照，不从 WebView 提交转写正文或证据；
- 总结快照必须属于当前 canonical `meeting` scope，或属于 Rust 为本次录音颁发的稳定 `recording_session` scope；原始 ASR `session_id` 不会被当作摘要 scope；
- 已撤回项目不显示；底部“证据刻度轨”只呈现去重后的证据数和更新时间，不暴露会议原文；
- 模式按钮支持 Tab、方向键、Home、End，并提供窗口聚焦时的 `Alt+1/2/3` 快捷切换。

当前已经是可承载字幕和结构化总结的“悬浮会议助手”。录音 start 会由 Rust 自动建立 opaque session scope 并发出公开快照；悬浮窗只在收到可信的 `session_started` 边界后接受该 scope 的后续修订，开始下一场录音时立即清空上一场状态。实时条目是否出现仍取决于用户是否配置可用总结 provider，以及 provider 是否返回通过证据校验的结构化结果。本切片没有伪造会话，也没有用旧会议填充空态。屏幕分享保护已经有开关，但尚未完成各会议软件的兼容性验收。

## 窗口关系

```text
Meetily 主窗口
  ├─ 显示/隐藏悬浮字幕
  ├─ 调整字幕外观
  └─ 鼠标穿透恢复入口

系统托盘
  ├─ 显示/隐藏实时字幕
  └─ 开启/关闭鼠标穿透

字幕窗口（caption-overlay）
  ├─ 录音状态 + 字幕 / 要点 / 待办切换
  ├─ 字幕：最近两条有效原文及严格绑定的译文
  ├─ 要点 / 待办：当前会话的结构化总结 + 证据刻度轨
  └─ 设置 / 清空字幕 / 隐藏

设置窗口（caption-settings）
  └─ 独立于字幕窗口，可出现在其上方或下方
```

字幕设置保存在 Meetily 配置的数据目录。便携运行时会落到 `portable/app-data/caption-overlay-settings.json`，不会使用用户主目录作为首选位置。

## 为什么设置必须是独立窗口

早期版本把外观设置面板画在只有约 180 px 高的字幕窗口内部。即使网页元素使用较高的 `z-index`，WebView 的像素也不能绘制到原生窗口矩形之外；结果只能出现滚动条或内容裁切。

正确解法是创建第二个无边框原生窗口。用户点击悬浮窗齿轮时，Rust 读取字幕窗口和当前显示器的物理坐标，把设置窗口放到可见工作区。这样既能真正超出字幕条，又不会在多显示器负坐标或任务栏区域外打开。

设置窗默认仍是 `460 × 440` 逻辑像素。显示前会按当前屏幕的缩放比例换算为物理像素，并与真实工作区比较；工作区较小时，窗口最多缩到工作区减去边缘间距，设置正文通过内部滚动保持可访问。关闭设置只会隐藏独立窗口，不会重建字幕 WebView 或清空字幕、译文和总结状态。

## 视觉与交互原则

这一界面只承担一个任务：用户查看文档、设计稿或视频时，用一眼读完的方式看到当前讲话、稳定要点或明确待办。视觉采用克制的“烟黑玻璃”：底色 `#080A0E`，白色承载正文，翡翠绿 `#34D399` 表示监听、决定和行动，冰蓝 `#7DD3FC` 表示议题，琥珀色 `#FBBF24` 表示风险或待确认。没有下载字体，中文继续使用现有系统字族。

唯一有识别度的元素是内容底部的“证据刻度轨”。每个刻度代表当前视图中一条去重后的 revision-bound 证据，旁边显示证据总数与最后更新时间。它不是置信度，也不能点击展开原文；这样既能让用户知道总结是否有依据，又不会让悬浮窗变成拥挤的仪表盘。

最新字幕对比度和字号最高，上一句弱化为上下文。要点和待办使用无卡片堆叠的紧凑分隔行，窗口内最多展示最近四项，其余内容引导到主窗口查看。工具按钮只在悬停或键盘聚焦时出现，三模式切换始终可见。

设置窗口沿用相同材质，但把信息层级收紧为“当前值—滑杆—范围—开关—恢复默认”。所有文案从用户能控制的结果命名，例如“窗口高度”“背景不透明度”“鼠标穿透”和“屏幕分享保护”，不暴露 WebView、内部事件名或错误堆栈。

透明度为 0% 时仍保留文字阴影，避免浅色或复杂视频背景让字幕完全消失。动画仅用于“正在监听”的低频状态提示，避免 token 到达时造成整窗闪烁。

## 鼠标穿透不会把用户锁死

原生 `set_ignore_cursor_events(true)` 会让整个字幕窗口收不到鼠标事件，窗口内按钮自然也无法关闭该状态。因此启用开关前必须始终存在窗口外恢复入口。

当前提供两条：

1. Meetily 主窗口的字幕设置按钮；
2. 系统托盘的“关闭字幕鼠标穿透”。

字幕标题也会显示“鼠标穿透已开启”。后续增加全局快捷键时，只能作为第三条入口，不能替代已有的可发现入口。

开关前的琥珀色提示会明确说明：开启后悬浮窗本身不再响应鼠标，Meetily 主窗口设置与系统托盘始终可以关闭。主窗口设置按钮在穿透开启时也会变为中文恢复提示。独立设置窗本身不会被设为穿透，因此从悬浮窗设置页开启后仍可立即关闭。

## 屏幕分享保护的边界

开启“屏幕分享保护”后，后端调用 Tauri 的系统窗口内容保护接口，请求操作系统阻止其他应用捕获字幕窗口。默认关闭，修改会与其他字幕外观设置一起保存在 D 盘数据目录。

它是尽力而为的系统能力，不是 DRM 或防泄漏保证。不同 Windows 版本、显卡驱动、会议软件的窗口/屏幕捕获路径可能出现“隐藏、黑块、仍然可见”三种结果。用户必须在实际使用的飞书、腾讯会议、OBS 或录屏工具中先做无敏感内容验收；失败时不影响字幕、转写和录音主链路。

## 如何避免隐藏期间丢字幕

WebView 事件不是可靠数据库。字幕窗口隐藏、重新创建或监听器尚未注册时，都可能错过 `transcript-update`。

当前窗口显示后会并行请求录音状态与转写历史，再把历史交给与主界面相同的 revision reducer。初始化请求带有本地请求序号和生命周期修订：如果请求返回前已经发生开始、暂停或停止事件，旧快照会被丢弃，避免“慢查询覆盖新状态”。

同一 `utterance_id` 的 partial、final、correction 和 retraction 由 reducer 物化为最新有效稿，UI 不靠简单字符串追加表达修订。

## 多显示器与 DPI

字幕尺寸由 Tauri 的 logical size 表达，允许操作系统按 DPI 缩放；设置窗定位读取两个窗口与显示器工作区的 physical position/size，避免把逻辑像素和物理像素直接相加。设置窗的默认逻辑尺寸先按目标显示器的 scale factor 转为物理尺寸，再与 work area 比较。

字幕窗移动后会把物理坐标防抖写入设置；重启、重新显示或窗口尺寸变化时，会选择离保存位置最近的显示器并把窗口矩形钳制到真实工作区。这样左侧/上方副屏的负坐标可以保留，拔掉原显示器后窗口也不会永久留在屏幕外。

仍需补充的边界包括：

- 100%、125%、150%、200% 缩放组合的自动化截图测试；
- Windows 任务栏置于屏幕左/上/右侧时的验收。

## 双语字幕如何工作

双语模式不把“最近两条原文”误解释成“原文 + 译文”。`BilingualCaptionLine` 的每个显示单元由一条原文及其严格绑定的译文组成：

```text
[日语原文 · 立即显示]
会議資料は来週までに更新してください。

[简体中文 · 异步补齐]
请在下周之前更新会议资料。
```

原文始终优先。译文失败、断网或 revision 不匹配时只显示原文，绝不能把上一句话的中文留在新日语下面。失败行固定显示“译文暂不可用，请检查翻译设置”，后端 provider 消息、内部错误码和堆栈不会进入用户界面。当前不会自动覆盖用户已有的窗口高度；双语内容较多时，用户可以在设置窗把高度调到 `220–240` 像素。

## 三种模式现在如何工作

同一悬浮宿主现在可以切换：

1. **字幕**：原文立即出现，译文异步补齐，优先保证最低感知延迟；
2. **要点**：只显示 `topic`、`decision`、`risk`、`open_question`；
3. **待办**：只显示 `action_item`，并在后端提供时附负责人和截止时间。

三种模式共享置顶、拖动、宽高、字号、透明度、鼠标穿透、屏幕分享保护和多屏定位。总结失败不会影响字幕，悬浮窗也不是录音事实来源：它只消费 `liveSummaryService.onState` 的公开事件，既不调用开始会话，也不向后端提交证据或转写正文。

前端 parser 先校验 `scope.kind + scope.id`、`sessionScopeId/meetingId` 形状、revision scope 以及每条 evidence scope；reducer 再按 `(generation, summaryRevision, transcriptCursor)` 保持单调顺序。同一位置按事件阶段防止迟到失败覆盖成功提交。空窗口只允许可信 `session_started` 建立 scope，跨会话的普通 commit/failed 事件不能抢占；明确的新 `session_started` 才能替换当前 scope。

悬浮窗重新挂载时只读取 Rust registry 中唯一的 active recording scope，并合成一次严格的 start 边界。pending scope 不会冒充正在录音，会话列表读取失败也不会连带破坏字幕或翻译初始化。应用进程重启会丢失内存 session，因此界面诚实显示空态，不从最近会议猜测摘要。

## 已遇到的问题与解决方式

### 设置面板被字幕窗口裁切

原因是 WebView 无法绘制到原生窗口外。解决方式是独立 `caption-settings` 原生窗口，并按当前显示器工作区定位。

### 鼠标穿透后无法操作字幕按钮

这是原生点击穿透的预期行为。解决方式是在主窗口和系统托盘保留恢复入口，并让设置持久化和菜单标签同步。

### 窗口隐藏再显示后状态过期

单靠事件订阅会漏掉隐藏期间的变化。解决方式是可取消的后台快照同步，加生命周期 revision 防止旧结果回写。

### 透明背景上的文字看不清

完全不透明的底板会遮住视频，完全透明又会丢失对比度。解决方式是用户可调的烟黑背景、透明时保留文字阴影，并限制低对比装饰。

### 多屏定位出现负坐标

Windows 左侧/上方副屏允许负坐标，不能把坐标强制钳到零。当前按显示器 work area 的真实左右上下边界钳制。

### 高缩放时设置窗大于可用工作区

`460 × 440` 逻辑像素在 200% 缩放下会成为 `920 × 880` 物理像素，小屏幕或较窄的远程桌面工作区可能放不下。当前根据目标屏幕的 scale factor 计算期望尺寸，再限制到 work area 内并保留 8 像素边缘；页面使用内部滚动，不让控件继续绘制到原生窗口外。纯函数测试覆盖 125%、150%、200%、负坐标副屏和工作区小于默认尺寸的情况。

### 实时总结事件可能属于上一场会议

单纯订阅全局事件会有串会风险。当前 parser 校验 snapshot、last revision 与 evidence 都使用同一个 `scope.kind + scope.id`；reducer 空态只接受 `session_started`，新录音的 `recording-started` 先清空旧状态。canonical 会议使用 `meetingId`，活动录音使用 Rust 颁发的 opaque `sessionScopeId`，两者不能混用，原始 ASR `session_id` 也不能冒充摘要 scope。没有可信 start、没有总结快照或 scope 不一致时只显示中文引导，不展示任何结构化事实。

### 总结失败或撤回后旧内容残留

迟到失败、重复快照和较旧 generation 可能倒退 UI，retraction 也不能继续显示。当前 reducer 拒绝乱序和重复快照，成功提交优先于同 revision 的失败事件；选择器与组件都只渲染非 `retracted` 项目。错误态使用固定的安全提示，不把 provider 原始错误铺到悬浮窗。

### 小窗口放不下三种模式和工具按钮

最小宽度仍保留 `360 px`。模式切换使用三段紧凑按钮，状态区和工具区允许收缩；正文最多显示最近四项并在需要时内部滚动。没有为了会议助手提高最小宽高，因此用户已有布局和多屏位置不会被重置。

## 验证清单

- 将字幕条调到最小和最大宽高，设置窗口仍完整可见；
- 字号 16/56 px、背景 0/100%，中日英混排不横向滚动；
- 字幕位于每块显示器四角时，设置窗仍处于该屏工作区；
- 关闭并重启后恢复字幕坐标；拔掉原显示器后重新显示，窗口回收到仍在线的最近工作区；
- 开启穿透后，底层视频可点击，主窗口和托盘都能关闭穿透；
- 开启分享保护后，用目标会议软件做窗口共享和整屏共享测试；关闭后字幕应恢复可捕获；
- 录音开始、暂停、恢复、停止以及转写错误时，中文状态正确；
- 隐藏字幕、产生新转写、重新显示，内容能从历史恢复；
- 重复、乱序、correction 和 retraction 不产生重复旧字幕；
- 字幕、要点、待办可用鼠标、Tab 和方向键切换，窗口聚焦时 `Alt+1/2/3` 生效；
- 没有可信 start、没有总结快照、scope 形状错误或跨 scope 时均不显示上一场会议内容；
- `topic/decision/risk/open_question` 只进入要点，`action_item` 只进入待办，`retracted` 永不出现；
- 证据刻度轨按 revision-bound 证据去重计数，显示公开快照的更新时间；
- 迟到 generation/revision 和跨会议非 `session_started` 事件不能倒退当前视图；
- 设置保存失败时给出明确状态，并回读后端实际值。
- 翻译失败事件即使携带英文 provider 信息或内部堆栈，悬浮窗也只显示固定简体中文安全提示。

## 尚未完成

- 活动录音 scope 已自动创建并在 save 后绑定 canonical 会议；总结 provider 未配置、模型失败或结构化结果无有效条目时，要点/待办仍会保持安全空态；
- WebView 重载可读取当前 Rust 进程中唯一 active scope；应用进程重启不会恢复尚未绑定的内存 session，也不会通过最近会议 ID 猜测旧快照；
- 会话绑定返回 `pending_retry` 后尚无悬浮窗或主界面的自动重试入口；逐字稿与录音不受影响；
- 证据刻度轨只有数量与更新时间，尚无跳转到主窗口证据原文的入口；
- `Alt+1/2/3` 只在悬浮窗获得焦点时有效，尚无系统级全局快捷键与用户可编辑按键；
- 屏幕分享保护在主流会议/录屏软件中的兼容性矩阵；
